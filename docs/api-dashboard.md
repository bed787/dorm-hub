# Панель API в Grafana

Это дополнение к уже установленному обновлению статистики и мониторинга.
Новый экран: **Модерация → Статистика → API: запросы и ошибки**.
В Grafana его также можно найти через **Dashboards → Dorm Hub → Dorm Hub — API**.

## Что видно

- Фильтры приложения, HTTP-метода и ручки; можно выбрать несколько значений.
- Раздел «API» скрывает HTML, статику и служебные проверки. «Все запросы» включает их.
- Период выбирается стандартным переключателем Grafana сверху справа.
- Общее число запросов, среднее время и p95, ошибки 4xx/5xx.
- Графики среднего времени, p95, запросов в секунду и числа вызовов по ручкам.
- Доли запросов и суммарного времени обработки по ручкам.
- Таблица: метод/ручка, вызовы, 2xx/3xx/4xx/5xx, суммарное и среднее время,
  p50/p95/p99, процент ошибок и средняя частота запросов.
- Отдельные графики кодов ответа, 4xx, 5xx и сравнения среднего/p50/p95/p99.

Ручка — это шаблон вроде `GET /api/listings/{id}`, а не отдельный URL каждого
объявления. В метриках нет пользовательских ID и поисковых запросов.
Панель использует уже существующие метрики HTTP; их история сохраняется.
В обновлении также добавлены интервалы 1, 2,5, 5 и 25 мс для более точного
отображения быстрых запросов. Новые интервалы начинают заполняться после деплоя.

Среднее — суммарное время, делённое на число запросов. Процентили приближённые,
рассчитываются по гистограмме. p95 означает, что около 95% запросов были быстрее
этого значения. Суммарное время включает ожидание БД/SMTP, это не время CPU.
4xx не всегда означают поломку: сюда входят, например, неверный код входа и отказ
в доступе. Счётчики за период рассчитываются через `increase`, поэтому это оценка
по периодическим замерам, учитывающая перезапуски, а не точный журнал запросов.
В таблице видны методы, по которым уже собраны метрики. Отказы до определения
маршрута попадают в `unmatched` и видны в режиме «Все запросы». Если данных нет, показан
прочерк; ноль означает, что данные есть, но вызовов за выбранный период не было.

## Обновить проект и запушить — на Mac

```bash
unzip -o ~/Downloads/dorm-hub-api-dashboard.zip -d ~/Desktop/projects &&
cd ~/Desktop/projects/dorm-hub &&
git add internal/platform/telemetry web/assets/admin-analytics.js deploy/monitoring tests docs/api-dashboard.md &&
git commit -m "Add detailed API dashboard" &&
git -c http.version=HTTP/1.1 push origin main
```

Дождись успешного workflow **Deploy website**. Он обновит приложение с новой
кнопкой и точностью гистограммы. Затем нужно перенести файл панели в установленную
Grafana: обычный деплой приложения не копирует конфигурацию мониторинга.

## Обновить панель — один раз на VPS

```bash
set -o pipefail
git -C /opt/dorm-hub fetch origin main &&
git -C /opt/dorm-hub show origin/main:deploy/monitoring/update-http-dashboard.sh | bash
```

Команда читает новый файл из GitHub и атомарно заменяет только файл панели в
`/etc/dorm-hub-monitoring/config/grafana/dashboards`. Контейнеры перезапускать не
нужно; Grafana подхватит панель примерно за 10–30 секунд. Прежний серверный
дашборд, настройки входа и история Prometheus сохраняются.

Если мониторинг ещё не установлен, сначала выполни разовую установку из
`docs/monitoring.md`. Затем открой:
https://dorm-hub.ru/monitoring/d/dorm-hub-http/dorm-hub-api

После обновления дай накопиться хотя бы нескольким замерам; для оценки новых
интервалов времени выбирай период после деплоя. Интервал
сбора остаётся 30 секунд, история — 7 дней; дополнительные контейнеры не нужны.
