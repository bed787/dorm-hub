# Технические работы

Режим управляется в интерфейсе администратора:
**Модерация → Доступ к сайту → Закрыть на технические работы**.
Для открытия используется кнопка **Открыть сайт**. Обе операции требуют
подтверждения; API дополнительно проверяет администратора, Origin и CSRF.

По умолчанию после установки режим выключен. Состояние хранится в новой
таблице `site_settings`; миграция `005_site_settings.sql` создаёт её один раз.
Последующие перезапуски и автоматические обновления не сбрасывают состояние.
Пользовательские данные, объявления и фотографии миграция не изменяет.

## Поведение

- Посетители без административной сессии получают HTML-заглушку с HTTP 503,
  `Cache-Control: no-store` и `Retry-After`. Закрыты также прямые API-запросы,
  фотографии и изменения от уже вошедших обычных пользователей.
- Открытая вкладка участника показывает заглушку при следующем API-запросе.
  Содержимое, уже загруженное в браузер до включения, удалённо отозвать нельзя.
- Регистрация и вход обычных пользователей блокируются до отправки письма,
  создания пользователя и сессии.
- Администратор продолжает пользоваться всеми разделами. В интерфейсе
  отображается уведомление о включённом режиме.
- Если администратор вышел, он может войти через `/admin-login` привычным
  кодом из письма. Допускаются адреса из ADMIN_EMAILS и существующие аккаунты
  с is_admin; заблокированный аккаунт по-прежнему не может войти.
  Сам адрес страницы не даёт никаких дополнительных прав.
- `/health`, `/ready`, статические файлы оформления и выход из аккаунта
  доступны. Healthcheck Docker и автоматическая выкладка продолжают работать.
- Заглушка содержит кнопку проверки доступности и ссылку на вход администратора.

## Установка на Mac

Архив содержит только изменённые и новые файлы этой функции. CSS, логотип,
секреты окружения и настройки GitHub Actions в него не входят.

```bash
cd /Users/ruslan/Desktop/projects/dorm-hub
unzip -o ~/Downloads/dorm-hub-maintenance.zip -d .
git add internal/httpapi web tests docs/maintenance.md
git add -f migrations/005_site_settings.sql
git commit -m "Add administrator maintenance switch"
git push
```

Дождитесь успешной выкладки в GitHub Actions. Миграция выполнится приложением
при запуске; выполнять SQL вручную не нужно. Войдите администратором и включите
режим в разделе «Доступ к сайту».

Отдельный Python-скрипт устанавливать не требуется. Если старый вариант уже был
включён через Caddy, сначала отключите его на сервере командой
`site-maintenance off`, иначе запросы не дойдут до приложения и админки.

## API

- `GET /api/admin/site-settings` → `{"data":{"maintenance":false}}`.
- `PUT /api/admin/site-settings` с `{"maintenance":true}` или false.
- Закрытые пользовательские API возвращают 503 с `error.code = "maintenance"`.

Включение блокирует новые запросы. Запрос, уже выполнявшийся в момент
переключения, может завершиться. Это режим доступа приложения, а не способ
управления отказавшим Go-процессом.

## Проверка

Пройдены go vet, Go-тесты и интеграционные тесты с проверкой гонок на тестовой
PostgreSQL-совместимой базе, 32 Node-теста и проверка DOM с реальными HTTP/SMTP:
кнопки включения/открытия, блокировка действующей пользовательской сессии,
страница HTTP 503, отказ обычному адресу во входе и повторный вход администратора.
