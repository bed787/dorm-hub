# Технические работы

Режим переключается в разделе «Модерация → Доступ к сайту» или через
`GET/PUT /api/admin/site-settings`. При включении обязательна причина длиной
до 1000 символов. Она показывается посетителям как текст; при открытии сайта
очищается. Состояние и причина хранятся в PostgreSQL и сохраняются при перезапуске.

```json
{"maintenance": true, "reason": "Обновление сервиса"}
```

Для открытия: `{"maintenance": false}`. Изменение требует административной
сессии, Origin и CSRF-токена.

## Доступ

- Обычные посетители получают HTML-страницу с HTTP 503, `Cache-Control: no-store`
  и `Retry-After`. Вход, регистрация, пользовательские API и фотографии закрыты.
- Открытая вкладка участника переключается на эту страницу при следующем запросе.
  Уже загруженные данные остаются в браузере; выполняющийся запрос может завершиться.
- Администраторы продолжают работу. Повторный вход доступен через `/admin-login`.
- `/health`, `/ready`, статические файлы, выход из аккаунта и публичные документы
  остаются доступны. Действующие сессии не удаляются.

Закрытый API возвращает `error.code = "maintenance"` и `error.reason`, чтобы
клиент показывал ту же причину. Режим ограничивает доступ к работающему приложению;
для диагностики сбоя самого процесса используются логи и мониторинг.
