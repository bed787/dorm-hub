# Публичные страницы и документы

| Маршрут | Назначение |
|---|---|
| `/` | Главная для гостей; действующая сессия перенаправляется в `/app` |
| `/about` | Описание площадки и FAQ |
| `/login` | Вход участника по почте |
| `/admin-login` | Вход администратора |
| `/rules`, `/privacy`, `/consent` | Правила, политика обработки данных и согласие |
| `/robots.txt`, `/sitemap.xml` | Данные для поисковых роботов |

Страницы формируются сервером из HTML-шаблонов пакета `web`. Ссылки входа
учитывают действующую серверную сессию. Статические ресурсы получают версию
по хешу содержимого, чтобы браузер обновлял их вместе с приложением.

## Тексты и контакты

Описание и FAQ находятся в `web/landing.html`, документы — в `web/legal.html`.
Название сообщества, город и Telegram администрации задаются в `web/site.json`:

```json
{
  "campus": "СПбГУ",
  "city": "Санкт-Петербург",
  "support_telegram": "@username"
}
```

Telegram можно указать именем или ссылкой `https://t.me/username`. Пустое значение
скрывает ссылку. Эти файлы встроены в бинарник; изменения требуют пересборки.

## Подтверждение документов

При обычном входе пользователь отдельно принимает правила и согласие.
Браузер получает их версии через `GET /api/auth/bootstrap` и передаёт при запросе
кода. Сервер проверяет версии и подтверждения до отправки письма.

Снимки HTML и их SHA-256 берутся из серверной сборки. Они сохраняются вместе
с временем запроса и подтверждения почты. Вход с той же парой версий не создаёт
дубликат; удаление аккаунта удаляет подтверждения. Административный вход не
требует флажков обычной регистрации и не создаёт такие записи.

Изменение текста или реквизитов документа меняет его версию. Документы доступны
и во время технических работ; подробности — в [maintenance.md](maintenance.md).
