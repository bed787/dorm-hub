# Главная, FAQ, документы и подтверждение согласия

## Что добавлено

- `/` — открытая главная для новых посетителей; действующие сессии перенаправляются на `/app` до отправки HTML. `/about` всегда открывает описание. Главная содержит: назначение площадки, категории, порядок работы и FAQ. Текст отдаётся сервером в HTML, без обязательного JavaScript и входа.
- `/login` — вход по почте. Согласие на обработку данных и правила принимаются двумя раздельными галочками; они не предустановлены.
- `/rules`, `/privacy`, `/consent` — отдельные открытые страницы. Ссылки есть на главной, при входе, в меню площадки и на экране технических работ.
- `/robots.txt`, `/sitemap.xml`, заголовок страницы, описание, canonical и Open Graph — основа для поисковой индексации. Фактическая индексация и позиции не гарантируются.
- Вошедший пользователь сразу попадает в ленту. После выхода или удаления аккаунта с главной возвращается открытая страница. После выхода интерфейс возвращается к публичной главной. Ссылка на конкретное объявление сохраняется при обычном входе.

Логотип `web/assets/brand.png` используется в шапке площадки, на главной, при входе и технических работах. Размеры шапки и логотипа задаются в едином блоке навигации `web/assets/app.css`; публичные страницы оформляет `web/assets/public.css`. Иконка вкладки остаётся отдельным небольшим SVG.

## Контакт администрации

Контакт для обращений — Telegram. Укажи его в `web/site.json`:

```json
{
  "campus": "СПбГУ",
  "city": "Санкт-Петербург",
  "support_telegram": "@username"
}
```

Вместо `@username` впиши свой адрес; также можно вставить `https://t.me/username`. Ссылка появится в подвале, FAQ, правилах, политике и согласии. Если значение пустое, публичные страницы не показывают ссылку и не выводят заглушек. В текстах пока остаётся общее обращение к администрации.

Тексты правил, политики и согласия находятся в `web/legal.html`. FAQ и описание — в `web/landing.html`. Версии документов определяются автоматически по их содержимому; публичная дата для этого не нужна.

## Как сохраняется согласие

1. Браузер получает актуальные идентификаторы документов через `GET /api/auth/bootstrap`.
2. При запросе кода отправляет `consent: true`, `rules: true` и обе версии. Сервер проверяет поля и версии до сохранения почты и отправки письма. Снятая галочка, прямой запрос без подтверждения или устаревшая версия не проходят.
3. Сервер берёт тексты из своей сборки и прикрепляет их с датой подтверждения к запросу кода. Текст от клиента не принимается.
4. После правильного кода из письма подтверждение связывается с аккаунтом в `user_legal_acceptances`. До подтверждения почты записи согласия у аккаунта нет.
5. Сохраняются точные HTML-фрагменты согласия и правил, их SHA-256 как версии, время действия и время проверки почты. Подтверждение действует в рамках конкретной пары текстов; повторный вход с той же парой не создаёт дубликаты.
6. Полное удаление аккаунта удаляет и эти записи через `ON DELETE CASCADE`. Неподтверждённый запрос кода для той же почты также удаляется штатным удалением аккаунта.

Для простоты галочки запрашиваются при каждом входе, в том числе у существующих пользователей. Уже открытые сессии не сбрасываются. Согласия задним числом не создаются. Код, запрошенный старой версией приложения без подтверждения, потребуется запросить заново.

Это техническая фиксация обычного согласия на обработку. Отдельная форма согласия на распространение контактов в это обновление не входит; универсальная галочка не представляется заменой такой формы. Места хранения у почтового провайдера, договоры и резервные копии не меняются этим обновлением. Проверяй соответствие опубликованной политики своей реальной эксплуатации, особенно при добавлении новых сервисов и копий.

## Технические работы

Режим не сбрасывается при обновлении. Если он включён, главная по-прежнему показывает причину и отвечает 503; обычный вход и закрытые API недоступны. Для поискового робота это тоже означает временную недоступность главной. Правила, политика и согласие остаются доступны. Администратор входит через `/admin-login` с теми же проверками роли и отдельными галочками.

## Установка на ноутбуке и выкладка

Распакуй содержимое архива в `/Users/ruslan/Desktop/projects/dorm-hub` с заменой совпадающих файлов. Это обновление для версии проекта с режимом технических работ, которую мы ранее подготовили. Оно не заменяет `.env`, Compose или настройки Caddy. В проверке от 17 октября также обновлены стили, логотип и CI; подробности — в `docs/review-2026-10-17.md`.

Укажи Telegram в `web/site.json`, проверь тексты и локально запусти привычной командой:

```bash
docker compose up -d --build
```

Затем в терминале **на Mac**, из папки проекта:

```bash
git add internal/auth internal/httpapi web tests/integration docs/public-pages.md
git add -f migrations/007_legal_acceptances.sql web/site.json web/web_test.go tests/integration/legal_test.go
git commit -m "Add public homepage, FAQ and legal acceptance"
git push
```

Уже настроенный GitHub Actions соберёт образ и обновит приложение. Миграция `007_legal_acceptances.sql` выполнится при запуске автоматически; существующие пользователи, объявления и фотографии не удаляются. Запускать `docker compose down -v` не нужно.

После открытия сайта для пользователей можно добавить домен в Яндекс Вебмастер / Google Search Console и отправить `/sitemap.xml`. Внешние кабинеты и индексация этим архивом автоматически не настраиваются.
