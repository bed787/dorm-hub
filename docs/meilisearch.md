# Поиск Meilisearch

Meilisearch обслуживает поиск в общей ленте и избранном.
Он ищет по названию и описанию, учитывает опечатки и начало слова. Название
имеет приоритет перед описанием. Настроены синонимы: «СВЧ» / «микроволновка»,
«холодос» / «холодильник», «общага» / «общежитие».

В индекс попадают только опубликованные объявления доступных пользователей.
Для черновиков, личного архива и модерации сохраняется поиск PostgreSQL.

## Один раз на сервере

Подключись по SSH и выполни:

```bash
cd /opt/dorm-hub &&
git pull --ff-only &&
bash deploy/install-server.sh --search
```

Установщик в режиме `--search` создаёт случайный
`MEILI_MASTER_KEY` в серверном `.env.production`, если ключа ещё нет, обновляет
установленный Compose, поднимает Meilisearch и пересоздаёт контейнер приложения
с текущим образом. Перенастраивать GitHub Secrets или SSH-ключи не требуется.

База, фотографии и режим технических работ сохраняются. Установщик использует
ту же блокировку, что автоматический деплой; одновременные операции ждут друг
друга. При неудаче восстанавливается предыдущая конфигурация Compose. Повторный
запуск сохраняет ключ и том поисковика.

Дальнейшие обновления приложения выполняются через автоматический деплой.
Meilisearch перезапускается Docker автоматически после перезагрузки сервера.

## Настройки и проверка

- Образ: `getmeili/meilisearch:v1.55.0`, без плавающего `latest`.
- Данные: отдельный том `dorm-hub_meilisearch`, каталог `/meili_data`.
- Порт 7700 не публикуется на хосте. Caddy для него не настраивается.
- Верхний лимит памяти контейнера — 512 МБ; бюджет индексации — 128 MiB,
  один поток индексации. Это настройки ограничения нагрузки, а не обещание
  постоянного потребления указанного объёма.
- `MEILI_URL` и `MEILI_MASTER_KEY` доступны только серверному приложению.
  Master key используется для получения ключа с доступом только к индексу
  `dormhub_listings`; обычные запросы используют этот ограниченный ключ.
- При локальном запуске через `docker compose up -d --build` Meilisearch
  поднимается вместе с остальными сервисами. Для разработки задан отдельный
  стандартный ключ, production Compose требует ключ из окружения.

В журналах приложения после индексации появляется `Meilisearch index ready`.
Эту запись можно найти в админской панели в разделе логов. Если движок
недоступен, появляется предупреждение об использовании PostgreSQL. В этом
режиме поиск временно выполняется в PostgreSQL.

## Как устроена синхронизация

Миграция 009 создаёт `search_index_queue`. Изменения объявлений и доступности
автора записывают ID в очередь в той же транзакции, что основное изменение.
Удалённые объявления оставляют задание на удаление из индекса; FK на listings
у очереди нет. Текст, почта и контакты в очереди не хранятся.

Фоновый обработчик отправляет актуальные опубликованные тексты в Meilisearch
или удаляет недоступные записи. Он ждёт завершения асинхронных задач движка
перед подтверждением обработки. Номер поколения защищает изменение, сделанное
во время индексации: обработчик не удалит более новое задание. После сбоя
задания повторяются. При запуске и восстановлении индекс перестраивается из БД;
до завершения работает резервный поиск.

В индекс передаются только ID, revision, название и описание. Отдельные поля
почты, контактов, адреса и комментария модератора не передаются. Поскольку сам
текст объявления вводит автор, он может содержать эти сведения.

Выдача Meilisearch используется как ранжированный набор ID и ревизий.
Фильтры, доступность, избранное, пагинация и содержимое карточек проверяются
PostgreSQL. Снятое с публикации или устаревшее объявление не выводится даже
до обработки очереди. Физическое удаление его поисковой копии происходит
фоновым обработчиком после восстановления доступности движка.

Для запроса, достигающего лимита в 10 000 кандидатов, используется PostgreSQL,
чтобы широкий запрос не терял объявления из-за ограничения поискового индекса.

## Проверки

`internal/platform/search/client_test.go` проверяет HTTP-клиент, ограниченный ключ,
ожидание задач, ошибки и отмену запросов. `tests/integration/search_test.go`
проверяет доступность объявлений, фильтры, ревизии, очередь и резервный поиск.
Тест настоящего движка включён в GitHub Actions и `compose.test.yaml`.
