# Статистика и мониторинг Dorm Hub

## Что появится

**Модерация → Статистика**: активные пользователи за день, 7 и 30 дней, первые
публикации, просмотры и переходы к контактам. Есть график по дням, таблица объявлений,
количество ожидающих модерации и возраст самой старой заявки.

**Мониторинг сервера** из этой вкладки открывает Grafana на
`https://dorm-hub.ru/monitoring/`. Сначала нужна действующая админская сессия
Dorm Hub, затем отдельный вход Grafana. Самостоятельный домен и изменения Caddy
для этого не нужны.

## Установка обновления на Mac

Архив содержит только новые и изменённые файлы, с папкой `dorm-hub` внутри.
Он устанавливается поверх версии с новыми категориями и SVG-иконками.

```bash
unzip -o ~/Downloads/dorm-hub-monitoring.zip -d ~/Desktop/projects &&
cd ~/Desktop/projects/dorm-hub &&
git add internal web deploy tests docs .github &&
git add -f go.mod go.sum migrations/012_analytics.sql &&
git commit -m "Add analytics and server monitoring" &&
git -c http.version=HTTP/1.1 push origin main
```

Дождись успешного workflow **Deploy website**. Вкладка «Статистика» начнёт
работать после обновления приложения. Контейнеры мониторинга устанавливаются
один раз отдельным следующим шагом.

Для проверки только на ноутбуке после распаковки достаточно:

```bash
cd ~/Desktop/projects/dorm-hub &&
docker compose --env-file /dev/null -f compose.yaml up -d --build
```

Статистика доступна локальному администратору `admin@students.example`, письма —
на http://localhost:8025. Для появления активности используй обычный аккаунт
`student@students.example`. Сборщик ресурсов VPS устанавливается на Linux-сервере.

## Один раз на сервере

Подключись по SSH. Команда ниже получает установочные файлы из GitHub во временную
папку. Она не делает `git pull` поверх старых файлов сервера и не заменяет
рабочую папку проекта.

```bash
set -o pipefail
cd /opt/dorm-hub &&
git fetch origin main &&
monitoring_source=$(mktemp -d /tmp/dorm-hub-monitoring.XXXXXX) &&
git archive origin/main deploy/monitoring deploy/server-deploy.sh | tar -x -C "$monitoring_source" &&
bash "$monitoring_source/deploy/monitoring/install.sh"
```

Установщик запускает три контейнера мониторинга, подключает приватную сеть к
приложению и пересоздаёт только контейнер приложения. Возможен короткий перерыв
на его запуск. База, фотографии, `.env.production`, SMTP и состояние технических
работ сохраняются. При ошибке установщик восстанавливает прежние настройки
приложения. Конфигурации мониторинга сохраняются в `/etc/dorm-hub-monitoring`.

Логин Grafana — `admin`. Посмотреть автоматически созданный пароль **на сервере**:

```bash
sed -n 's/^GRAFANA_ADMIN_PASSWORD=/Пароль Grafana: /p' /etc/dorm-hub-monitoring/secrets.env
```

Пароль и ключ Grafana создаются один раз и сохраняются при повторной установке.
После входа откроется готовая панель. Её также можно найти через
**Dashboards → Dorm Hub → Dorm Hub — сервер**.

Последующие пуши используют установленную конфигурацию мониторинга автоматически.
Если меняются сами файлы `deploy/monitoring`, повтори установочный шаг с GitHub.

## Что считается

- Дни — по московскому времени. «7 дней» и «30 дней» включают сегодняшний день.
- Один пользователь учитывается один раз за день. WAU/MAU — уникальные люди,
  а не сумма дневных значений. Проверки `/me`, healthcheck и админские запросы
  активность не накручивают.
- Просмотр — успешное открытие доступного опубликованного объявления через API.
  Для пользователя и объявления учитывается один просмотр за день.
- Telegram и VK считаются отдельно, не больше одного перехода по каждому каналу
  для пользователя и объявления за день. Это признак интереса, не подтверждение сделки.
- Собственные просмотры/переходы и действия администраторов исключены.
- Первая публикация и первое успешное завершение запоминаются в базе. Повторная
  модерация или повторное завершение не создают второе событие.
- Новые пользователи считаются по дате создания аккаунта, без администраторов.
- История активности и переходов начинается с установки; прошлые посещения
  восстановить нельзя. Даты старых публикаций восстанавливаются только при
  наличии записи об одобрении модератором.
- Записи активности/переходов хранятся до 90 дней. Удаление аккаунта очищает его
  записи; удаление объявления очищает его просмотры и переходы. Поэтому история
  может уменьшаться после удаления. Существующий общий обезличенный счётчик
  успешных сделок сохраняет прежнее поведение.

## Ресурсы и доступ

Prometheus и Grafana имеют лимиты по 512 МиБ ОЗУ, Node Exporter — 64 МиБ. Невысокий
CPU priority позволяет приложению получать больше процессорного времени при
конкуренции. История технических метрик — 7 дней, сбор раз в 30 секунд.
Для блоков Prometheus задан бюджет 1 ГБ; WAL и временные данные занимают место
сверх него, поэтому ориентир для его тома — около 2 ГБ.

Порты Grafana, Prometheus, Node Exporter и `/metrics` не опубликованы в интернете.
У приложения отдельный служебный порт только в Docker-сети. В метриках нет почт,
пользовательских ID, текстов запросов и названий объявлений. Docker socket не
передаётся контейнерам. Node Exporter читает системные показатели через read-only
монтирование файловой системы VPS.

Графики содержат состояние приложения/БД, CPU, ОЗУ, свободный диск, запросы,
5xx, p95 времени ответа, успешные/неуспешные попытки SMTP и ошибки записи статистики.
Успешная SMTP-попытка означает принятие письма почтовым сервером, не его появление
во входящих получателя.

## Сигналы о проблемах

В Prometheus подготовлены правила: приложение недоступно 2 минуты, недоступна БД,
ошибки SMTP, повторяющиеся 5xx, мало места или памяти. Срабатывания видны в панели
Grafana. Запланированный режим технических работ не вызывает сигнал о 5xx.

Отправка уведомлений в почту/мессенджер не включена: для неё нужно отдельно выбрать
получателя и канал доставки и подключить обработку этих сигналов. Полное падение
VPS отслеживается внешней проверкой: мониторинг на том же VPS при этом тоже остановится.

## Проверки и диагностика

На сервере:

```bash
docker stats --no-stream
docker compose --project-name dorm-hub-monitoring --env-file /etc/dorm-hub-monitoring/secrets.env -f /etc/dorm-hub-monitoring/config/compose.yaml ps
docker compose --project-name dorm-hub-monitoring --env-file /etc/dorm-hub-monitoring/secrets.env -f /etc/dorm-hub-monitoring/config/compose.yaml logs --tail=80
```

Локальные проверки изменений: Node-тесты, Go-тесты, SQL-сценарии на PGlite,
`go vet`, сборка, `govulncheck`, проверка правил Prometheus настоящим `promtool`.
В workflow также добавлен Docker smoke test: конфигурация Prometheus, правила,
запуск Grafana и загрузка подготовленного dashboard. Его результат нужно проверить
в GitHub Actions: здесь Docker daemon и браузерный preview недоступны.

## Где находится код

- `internal/analytics` — запись и сводки статистики из PostgreSQL.
- `migrations/012_analytics.sql` — таблицы, индексы, даты первых событий.
- `internal/platform/telemetry` — Prometheus registry и учёт SMTP.
- `internal/httpapi/analytics.go` — закрытый API статистики и приём событий.
- `internal/httpapi/monitoring.go` — доступ администратора к Grafana.
- `web/assets/admin-analytics.js` и `analytics.css` — интерфейс статистики.
- `deploy/monitoring` — контейнеры, конфигурации, dashboard, правила и установщик.
