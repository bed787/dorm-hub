# Dorm Hub

Независимый студенческий проект: закрытая площадка объявлений. Сервер на Go,
PostgreSQL, обычные HTML/CSS/JavaScript. Интерфейс и миграции встроены в Go-программу.

## Запуск на своём компьютере

Нужен Docker с Compose. В папке проекта:

```bash
cp .env.example .env
docker compose up -d --build
```

Открой http://localhost:8080. Тестовые письма: http://localhost:8025.
Вход участника: `student@students.example`, администратора: `admin@students.example`.
Код приходит в Mailpit, а не в настоящий почтовый ящик.

Для существующего проекта сохрани свой локальный `.env`: в выдаваемом архиве его
нет. После замены исходников выполни `docker compose up -d --build` и обнови вкладку.
Миграции применяются автоматически. До обновления сделай копию тестовых данных,
если они нужны. Старые локальные активные объявления переводятся на проверку:
публичного запуска этой версии ещё не было.

```bash
docker compose down       # остановить, оставить данные
docker compose down -v    # остановить и удалить базу И фотографии
```

## Телефон и локальная сеть

В режиме `APP_ENV=development` можно открывать сайт по `http://IP-компьютера:8080`
и по `http://localhost:8080`. Запрос должен приходить со страницы, открытой по
тому же адресу, что и сервер: другой сайт, IP или порт не допускаются. CSRF
продолжает проверяться. Настраивать дополнительные разрешённые адреса не нужно.
Обычный compose.yaml уже публикует порт для локальной сети. Production Compose
предназначен для обратного прокси, а в production Origin остаётся привязан к BASE_URL.

После обновления исходников:

```bash
docker compose up -d --build --force-recreate app
```

Удалять базу для применения настроек и этого исправления не требуется.

## Объявления

Четыре раздела в «Моих объявлениях»:

- **Опубликовано** — одобрено модератором и доступно участникам.
- **На проверке** — отправлено автором; видит автор и модератор.
- **Архив** — черновики, отложенные и отклонённые объявления. При отказе сохраняется
  комментарий модератора, текст, фото и контакты.
- **Завершено** — завершено автором. Видит автор и модератор; автоматического переноса
  через 24 часа больше нет.

Незаконченная форма автоматически сохраняется в архив после паузы и перед
переходом на другую страницу. Пустая новая форма не создаёт объявление.
Дополнительно браузер хранит копию незавершённого редактора в IndexedDB, включая
ожидающие загрузки фотографии и ключи повторов. После ошибки открой «Новое
объявление» или редактор того же объявления для восстановления. Если браузер
запрещает хранилище, ориентируйся на надпись о сохранении и не закрывай вкладку до
успешной отправки. Сохранение на сервере зависит от соединения.

При отправке на проверку нужны заполненные поля и хотя бы один HTTPS-контакт
Telegram/VK **в самом объявлении**. Можно вводить полную ссылку, `@username`
для Telegram или имя страницы VK: сервер преобразует их в HTTPS-ссылки. Профиль можно оставить без контактов.
Изменения контактов объявления не меняют профиль. Черновики допускают неполные
поля и незаконченные ссылки.

Во время редактирования автосохранение переносит объявление в приватный архив;
кнопка «Отправить на проверку» завершает редактирование и ставит его в очередь.
Любое изменение фото у опубликованного объявления снимает публикацию и требует
повторной проверки. Завершённое объявление при редактировании остаётся завершённым:
для возвращения нужна отдельная отправка на проверку.

В «Модерации → Объявления» открывай карточку, проверяй текст, фотографии и контакты,
затем одобряй или возвращай с обязательным комментарием. Если автор успел изменить
объявление, устаревшее одобрение не проходит: нужно открыть свежую версию.

Лимит: до 10 опубликованных объявлений и объявлений на проверке вместе; до 50
новых архивных черновиков. Фото: до 10 в объявлении; квота аккаунта по умолчанию
200 МиБ / 200 фото, включая архив и завершённые объявления.

## Завершённые сделки

Автор выбирает «Сделка состоялась / нужное найдено» или «Передумал / больше не
актуально». Первый вариант увеличивает общий счётчик **один раз на объявление**.
Счётчик не является проверенной репутацией и не показывается в профилях.
В шапке указан итог по отметкам участников. Удаление объявления или аккаунта не
уменьшает итог: в базе остаётся только агрегированное число.

## Удаление аккаунта

В профиле нажми «Удалить аккаунт». На почту придёт отдельный код удаления, действующий
10 минут, с лимитом 5 ошибочных попыток и повторной отправкой не чаще раза в минуту.
Код привязан к сессии, в которой запрошен, и не заменяется кодом входа.

Удаляются аккаунт, почта, контакты, объявления, фото, сессии, избранное, звёзды,
связанные жалобы, действия модераторов, ключи повторов и коды входа/удаления.
Повторный вход после удаления создаёт новый аккаунт. Восстановление удалённого
аккаунта отсутствует. Администратор также может удалить свой аккаунт.

Файлы удаляются после транзакции базы. При ошибке диска остаётся очередь с
случайными именами файлов без идентификатора аккаунта: очистка повторяется на
старте и раз в минуту. Очередь не заменяет резервные копии.

Исторические внешние бэкапы, письма в почтовом сервисе и копии на чужих устройствах
не очищаются этим кодом. Срок хранения бэкапов нужно определить при развёртывании;
после восстановления старого бэкапа удаление нужно применить повторно. Политика ПД
должна учитывать эти сроки и используемую почту. Юридические документы этим
обновлением не добавлены.

Логи HTTP содержат шаблон маршрута и технический статус, без почты, контактов,
текстов объявлений и конкретных ID в адресах. Старые журналы предыдущей версии
автоматически не переписываются.

## Проверки

```bash
node --test tests/*.test.cjs
docker compose -f compose.test.yaml up --abort-on-container-exit --exit-code-from tests
docker compose -f compose.test.yaml down
```

Интеграционные Go-тесты запускаются только с `TEST_DATABASE_URL`; имя базы должно
заканчиваться на `_test`. Тесты очищают её и не должны работать параллельно в одной
базе. Dockerfile запускает `go vet` и обычные тесты; для тестов базы нужен отдельный
тестовый Compose.

С локально установленным Go:

```bash
go mod download
go vet ./...
go test -race ./...
go build -o bin/dorm-hub ./cmd/api
```

## Публичное размещение

Скопируй `.env.production.example` в `.env.production`, заполни значения.
`BASE_URL` — точный HTTPS-адрес сайта без пути. Сгенерируй новый секрет через
`openssl rand -hex 32`. Укажи согласованные `POSTGRES_PASSWORD` и `DATABASE_URL`.
Настрой Caddy/Nginx с HTTPS на сервере: production Compose публикует приложение
только на `127.0.0.1:8080`. SMTP должен поддерживать STARTTLS; прямой SMTPS 465 не
реализован. Настройки почты доступны также при локальном запуске.

```bash
docker compose --env-file .env.production -f compose.production.yaml up -d --build
```

Изменение `POSTGRES_PASSWORD` не меняет пароль уже созданного пользователя базы.
Производственный и локальный Compose используют одно имя проекта и тома:
одновременно запускай только один вариант.

Структура и API: `docs/architecture.md`, `docs/api.md`.
Результаты проверки текущей версии: `docs/verification.md`.
